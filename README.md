# Career Portfolio

**데이터 분석·데이터 사이언스 직무를 위한 프로젝트 포트폴리오입니다.**
모델 점수만 보여주기보다 입력 데이터의 의미, 검증 방법, 확인하지 못한 결과를 함께 설명합니다.
목표 직무는 현재 프로젝트를 바탕으로 정리한 지원 방향이며 재직 직함이나 경력 인증이 아닙니다.

## 대표 프로젝트

### Stock — 같은 입력으로 연구를 다시 실행할 수 있는가?
원본 체결·호가를 보존하고 수집기, 운영 화면, 입력 검증, 이벤트 재생의 책임을 나눈 프로젝트입니다.
SQLite 잠금과 sidecar 처리에서 안전하지 않은 경계를 합성 회귀로 다룹니다.
**상태: 연구·검증 진행 중. 전체 실데이터 품질 검증과 첫 백테스트는 미완료이며 수익성을 주장하지 않습니다.**

[문제·설계·결과·한계](projects/stock.md) · [원본 저장소](https://github.com/Peter-jackson12/Stock)

### Airplane — 전처리가 타당해지면 성능도 좋아지는가?
항공편 데이터의 모호한 결측 대치를 줄이고 모델 선택과 최종 평가의 경계를 구분했습니다.
**결과: 전처리의 의미는 개선했지만 Macro F1 향상은 확인하지 못했습니다.**
날씨 수집은 끝났지만 전체 결합과 날씨 유무 모델 비교는 별도 검증 단계입니다.

[분석·평가·결과·한계](projects/airplane.md) · [원본 저장소](https://github.com/Peter-jackson12/Airplane)

## 기술을 확인하는 방법

Python은 두 프로젝트의 구현에서, SQLite·pytest는 Stock의 실패 경계 회귀에서,
scikit-learn·LightGBM은 Airplane의 평가 코드와 결과 설명에서 확인할 수 있습니다.
기술명만으로 숙련도를 표시하거나 점수 막대를 만들지 않습니다.
[근거 ID와 고정 출처 목록](generated/PROJECT_INDEX.md)에서 실제 파일로 이동할 수 있습니다.

개인 프로젝트 운영과 AI 도구를 사용한 작업을 단독 수작업 구현과 혼동하지 않습니다.
각 사례의 **My Role**은 프로젝트 수준에서 확인한 범위와 본인 확인이 필요한 기여를 구분합니다.
개인 기여 문장은 공개 제출 전 본인이 확인해야 합니다.
