## 대표 프로젝트: Stock

#### 실시간 틱 수집 운영과 비용 반영 전략 검증 연구

KRX·NXT 전체 세션의 체결·호가 원문을 매 거래일 수집·검사하고, 비용과 사전등록 규칙 아래에서 전략 후보를 검증하는 연구입니다.

![Stock 시스템 구조: 수집은 시세 공급원, 수집 프로세스, 원본 저장소, 종료 후 검사기, 보관 저장소로 이어지고 연구는 매일 준비 작업, 연구 입력 저장소, 틱 재생기, 전략 모듈과 가상 브로커, 결과 저장소로 이어지며 모의 계좌 연결 시험은 연구 경로와 연결되지 않은 별도 경로입니다.](docs/assets/projects/stock-architecture.svg)

- **수집 운영** — 행 수를 집계할 수 있는 11일의 합계 183,918,557행을 수집했고, 장 마감 뒤 자동으로 시작되는 읽기 전용 원본 검사(순번·체크섬·콜백 회계)로 판정합니다.
- **연구 방법** — 왕복 손익분기 약 0.2305%의 비용 기준, 사전등록·독립 리뷰·동결 뒤에만 후보로 인정하는 규칙, 시점 정합 유통주식 이력으로 누설·생존 편향을 막습니다.
- **현재 결과** — 2026-11-02 기준 채택된 후보는 없고, 기각 결과는 사례에 음수 그대로 적었습니다. 실거래·자동매매는 연결하지 않았습니다.
- **최근 검증** — 11/2 저장소 감사 수정 병합 뒤 합친 트리 전체 실행에서 5,678 passed · 0 failed · 35 skipped · 15 xfailed를 기록했습니다. 합성 자료 중심 검증이며 실데이터 품질 인증은 아닙니다.
- **규모** — Python 131,818줄, 테스트 함수 3,245개(2026-10-26 정적 집계이며 실행 통과 수가 아닙니다).

[**Stock 사례 읽기 →**](projects/stock.md) · 데이터 흐름·하루 운영·연구 판정 구조도와 대표 기술 사례를 담았습니다. 원본 저장소는 시장 데이터 이력 때문에 비공개이며, 코드는 요청하시면 보여 드릴 수 있습니다(시장 데이터 제외).

### AI TOP 100 예선 과제
#### 고객 응대 AI 에이전트를 5시간 안에 완성해 배포한 1인 참가 과제

사전에 준비한 봇 위에 당일 지식과 프롬프트를 완성해 카카오톡 채널 챗봇으로 배포했습니다. 출처 있는 사실만 답의 근거로 삼고, 제출 뒤에는 사람 조작 없이 돌아가도록 자동 재시작과 예비 LLM을 준비했습니다.

<img src="docs/assets/projects/ai-top100-architecture.svg" width="720" alt="AI TOP 100 예선 과제 구조: 수집 자료와 자체 전송 도구로 모은 대화를 정제·검산 스크립트로 다듬어 행마다 출처가 있는 사실 원장을 만들고, 프롬프트 생성과 배포 스크립트를 거쳐 로컬 봇 서버에 올립니다. 일괄 시험 결과는 사실 원장으로 되돌립니다. 봇 서버는 메신저 채널, LLM 1차·예비, 외부 업무 서버와 연결되고 watchdog이 자동으로 재시작합니다.">

결과는 본선 미진출(2026-11-04 안내)이고 공식 점수는 안내되지 않습니다. 사례의 수치는 모두 자체 시험·자체 기록이며, 문제 내용은 대회 안내에 따라 쓰지 않습니다.

### Airplane
#### 지연 예측과 날씨 정보 확장

전처리의 의미와 새 정보(날씨)의 예측력을 나눠 검증하도록 연구 방향·평가 경계·구현 통합을 맡았습니다.

<img src="docs/assets/projects/airplane-pipeline.svg" width="720" alt="Airplane 분석 구조: 원본 100만 행에서 전처리 질문과 날씨 질문을 나누어 서로 다른 평가 집단에서 검증한 흐름">

전처리 수정은 Macro F1 향상을 확인하지 못했고, 날씨 추가는 동일 180,332행·동일 폴드 비교에서 Macro F1 0.574 → 0.599 등 세 지표가 세 시드 모두 개선됐습니다(정적 교차검증, 인과 효과 아님).

## 개발 방식과 근거

Stock과 Airplane은 **개인 프로젝트**입니다. 문제 정의부터 설계·코드 통합·검증 기준·운영과 최종 의사결정까지 책임졌습니다.

ChatGPT·Claude·Codex/Claude Code를 구현·리뷰·디버깅·테스트·문서화 등의 개발 보조로 활용했습니다.
프로젝트 방향, 아키텍처, 검증 기준과 최종 결과의 채택·통합은 제가 통제했습니다.

[ownership 확인 범위](docs/OWNERSHIP.md)와 [코드·테스트 근거 인덱스](generated/PROJECT_INDEX.md)는 서로 다른 사실을 설명합니다.
기술 태그는 숙련도·채용 요건 충족 인증이 아닙니다. 목표 직무는 지원 방향이지 재직 직함이 아닙니다.
